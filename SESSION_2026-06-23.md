## Key technical decisions

| Decision | Why |
|---|---|
| Page tokens stored in `accounts.local.json`, not env | 5 accounts × multiline tokens = unmanageable in `.env`; JSON file is cleaner, easy to regenerate |
| Direct Meta API from dashboard (Phase 1) before Airtable | Fastest path to "see real data". Airtable adds value (historical) but adds setup; we'd rather show the user real numbers now |
| Stay in Meta Dev Mode (no App Review) | Internal use, accounts added as testers — Review only needed for external client accounts later |
| Date presets up to 1y | User explicitly asked: "if we have posted more than 100 posts in a month, will that all be visible?" — yes, with paginated API + larger preset |
| Hardcoded 500-post cap per request | Safety net against runaway pagination; can raise per request via `?limit=` |

## Quick reference — common questions

**Q: How fresh is the data on the dashboard?**
A: Every page hit calls Meta in real time. No caching. Engagement counters update in minutes; reach lags up to 48h (Meta-side delay).

**Q: How do I add a 6th account?**
A: Add a new entry to `lib/accounts.ts` and to `accounts.local.json` with its `igUserId` + `pageAccessToken`. No code changes needed.

**Q: How do I refresh the long-lived user token before it expires (60 days)?**
A: Phase 2 will automate this in n8n weekly. Manually for now: run the exchange URL in the browser console, replace `META_LONG_LIVED_USER_TOKEN` in `.env.local`, restart dev server.

**Q: Why is "Followers over time" flat?**
A: Meta API gives current follower count, not historical daily counts. To get a real trend curve, we need n8n to snapshot daily into Airtable (Phase 2).

**Q: Why doesn't Stories tab show old stories?**
A: Meta drops story data 24 hours after posting. Only way to keep them is webhook capture before expiry — Phase 2.

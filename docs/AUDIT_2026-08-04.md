## 🔒 Security

### 🔴 1. Broken access control — permissions enforced in UI only (High)
`hasCapability()` / `canAccessSection()` are called **only** in `app/(dashboard)/dashboard/hope-preview/team/page.tsx` (client). **No API route checks them.** Middleware enforces authentication but not authorization.
- Anchors: `app/api/marketing-hub/delete/route.ts` (comment admits "Gated in the UI"), plus `marketing-hub/update|create|takeover|collaborators`, and `app/api/leads-crm/route.ts` GET.
- Exploit: any authenticated user calls `POST /api/marketing-hub/delete {id}` to wipe any task, or `GET /api/leads-crm?from=…&to=…` to pull all sales-lead PII (names/phones) the UI hides from them.
- Fix: shared `requireCapability(cap)` / `requireSection(sec)` server guard mirroring `admin/team`'s `requireAdmin`; return 403 otherwise.

### 🔴 2. SSRF in the article reader (High)
`app/api/radar/article/route.ts:82-99` — the content GET uses `redirect: "follow"` and never re-validates the post-redirect host before returning the body (the sibling `radar/pdf` does re-check).
- Exploit: attacker server returns 200 to HEAD but `302 → http://169.254.169.254/…` to GET; a logged-in user opening the link makes the server fetch cloud-metadata and return it as "article" text.
- Fix: `redirect: "manual"` + re-run `assertPublicUrl` per hop, or `await assertPublicUrl(r.url)` after the GET before reading the body.

### 🟠 3. Stored/reflected XSS in the reader (Medium–High)
Source `app/api/radar/article/route.ts:132` returns Readability HTML **unsanitized** → sinks render it via `dangerouslySetInnerHTML` (`radar/page.tsx:1217,1372`, `CompetitorBriefing.tsx:549`). No DOMPurify anywhere in the app. Readability strips `<script>` but not `on*` handlers, so `<img src=x onerror=…>` fires in the authenticated origin.
- Fix: DOMPurify the reader HTML (drop all `on*`, non-http(s) `src`/`href`) before rendering.

### 🟡 4. Audit-log attribution spoofing (Low)
`marketing-hub/delete/route.ts:21` & `update/route.ts:124` — `actor = body.actor || getSessionUserId()`; caller can name anyone in the audit row. Fix: always use `getSessionUserId()`.

**✅ Verified clean:** HMAC session auth (constant-time), same-origin CSRF on all mutations, cron-secret checks, Google OAuth (`state` + `@goocampus.in` roster gate), Supabase service-role key server-only (no `NEXT_PUBLIC_` leak), parameterized queries (no SQLi), regex-validated Airtable date formulas. No command injection / eval / unsafe deserialization.
*Awareness (accepted design): sessions embed the admin flag for 7 days without re-validation.*

## 🐛 Correctness / bugs

### 🟠 1. Scheduler "best time" recommends the wrong day (Medium — confirmed)
`lib/instagram.ts:403` grid uses `getUTCDay()` (0=Sun); `lib/scheduler-helpers.ts:76` consumes it as 0=Mon (`DAY_LABELS`). Every suggested slot is shifted by the Sun/Mon offset. Secondary: `nextOccurrence` uses local-server `setHours` → "9 AM" drifts to 14:30 IST on UTC hosts. Fix: normalize grid to Mon-first; pin to Asia/Kolkata.

### 🟠 2. Multi-page scheduling clones a shared `airtable_record_id` (Medium — confirmed)
`app/api/scheduler/schedule-multi/route.ts:56` spreads `{...src}` (incl. `airtable_record_id` from line 40) without nulling it. Clones share the original's Airtable id → `mh-linkback` writes the published URL to the wrong row; unique constraint would fail the insert. Fix: `airtable_record_id: null` on clones.

### 🟡 3. Competitor YouTube views zero past 50 videos (Low — latent)
`benchmark/youtube/route.ts:56` sends all IDs in one `videos?id=` call (API caps at 50). Breaks at ~9+ channels. Fix: chunk ≤50.

## 🎨 Live design/QA pass (impeccable-style)

Representative walk of the running app (logged in as Maheen) — tabs sampled: Overview, My Workspace ▸ Briefing, Marketing Hub ▸ Master sheet, Scheduler. Not every one of the ~15 tabs; deeper per-tab passes available on request.

**Genuinely strong (no change needed):**
- Consistent Hope UI across tabs: indigo accent, sectioned cards with icon+title headers, gray canvas, no shadows.
- Excellent state encoding — semantic status colors (Scheduler: orange/blue/green/red count cards), status dots + avatar chips (Master sheet), live/fetching/token pills.
- Overview KPI insights are prescriptive and on-brand ("Shift 2 of the next 8 posts to reels", "pin 3 posts to AMC/DHA/NEET PG"), not metric restatements.
- Clear hierarchy; the per-section indigo hero orients each view.

**Polish opportunities (concrete):**
1. **[Med] Perceived speed is the weakest part.** Every tab shows "Loading…/Fetching…" on cold load (fresh server + live APIs). The perf findings above (per-instance `leads-crm` cache; unbounded `readSnapshots`) directly worsen this. Wins: skeletons that match final layout, cache-warm on nav, back caches with `discover_cache`.
2. **[Low] Z-index/overlap on Master sheet** — a blue floating action button sits partially *behind* the "Comment" widget (bottom-right); only on that tab. Offset or restack.
3. **[Low] Loading vs empty ambiguity** — Master sheet shows "0 tasks" *and* "Loading…" at once; the 0 reads as a real count before data arrives. Use a skeleton row count while fetching, distinct from a true empty state.
4. **[Opinion] Saturated indigo gradient hero on every tab** — it's the signature, but a full-width saturated banner on data-dense views (Master sheet, Scheduler) competes with content. Consider quieting secondary tabs to a lighter `bg-brand-light` bar so the data leads.
5. **[Trivial] Emoji in hero greetings (👋)** — the "emoji as accent" pattern; harmless once per view.

Overall: design maturity is high; this is a polish list, not a redesign.

## 🛡️ CSO pass — OWASP + STRIDE (2026-08-04)

Systematic pass (secrets, supply-chain, CI/CD, infra, OWASP Top 10). Supply chain is clean (no install/postinstall scripts, lockfile tracked, no CI workflows). Crypto (HMAC sessions, scrypt passwords), injection (regex-validated Supabase `.or()`/Airtable formulas), misconfig (full CSP + HSTS + frame-ancestors live in `netlify.toml`), and SSRF (both reader routes re-validate) all assessed **clean**.

### 🔴🔴 CRITICAL — live secrets committed to git
`.env.local.bak.1785733150` was **tracked and pushed** (`.gitignore` covered `.env.local` but not the `.bak`). Held 25+ real credentials: `SUPABASE_SECRET_KEY` (service-role, bypasses RLS), `SESSION_SECRET` (forge any session → admin), `CRON_SECRET`, `OPENAI_API_KEY`, `GA4_PRIVATE_KEY`, `AIRTABLE_API_KEY`, `NETLIFY_AUTH_TOKEN`, Meta/LinkedIn/YouTube tokens.

- **REQUIRED (user):** rotate every listed credential; scrub from git history (BFG/`git filter-repo` + coordinated force-push) — the values remain in history until then.

### 🟠 Access-control variants of the earlier fix
- **FIXED:** `leads-crm/counsellor` (GET returned lead names + mobile numbers, no gate) → `requireSection("sales")`. `diagnostics/reconnect` (any user could overwrite live OAuth tokens) → `requireSection("system")` (admin-only).
- **DEFERRED (verify-first):** `leads/social` and `leads` (GET) also lack the sales gate but feed broader widgets — gate them only after checking against a non-sales login so a shared view doesn't break.

### 🟠 Session revocation gap *(High — design)*
Sessions are stateless signed cookies (7-day), never re-checked against `ind_users`. A deactivated/demoted user keeps full access (incl. sales PII, admin impersonation) until expiry. Worsened by the leaked `SESSION_SECRET` (forgeable until rotated). Fix: revalidate `active`/`is_admin` (or a `session_epoch`) per request. Deferred — its own change.

### 🟡 Unbounded Perplexity spend *(Med, financial)*
Several LLM routes (`ai-insights`, `post-planner`, `overview-tips`, `website/insights`, `format-advisor`, `scheduler/suggest-caption`, `inbox`) call Perplexity with no `guardRate` (their peers have it). Auth-gated so internal-only, but add `guardRate` for parity. Deferred.

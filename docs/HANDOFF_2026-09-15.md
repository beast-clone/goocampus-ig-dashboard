## What was built today — Marketing Campaigns

A new tab that works an event's lead list **directly in its Google Sheet**. There is no
copy of the leads anywhere: they are read from the sheet on load and written straight
back. The only thing stored is the campaign's settings (a few hundred bytes in
`discover_cache`). See `docs/CAMPAIGNS_SPEC.md` for why.

Working and tested against the live Al Ameen sheet (173 leads):

- **Setup** — paste a sheet link or pick one already shared with the dashboard, choose
  the tab, choose the column that identifies a row (duplicates are refused), then a
  **mapping panel** fills every field from the headers and lets you change any of them.
  A box there creates a missing column in the sheet.
- **The table** — columns appear in the **sheet's own order**. Drag any header to
  reorder, drag its right edge to resize, × to hide (hidden ones return from chips
  above the table). Every column in the sheet is shown; the extra ones read-only.
- **Editing** — Status is a dropdown of values already in that column, with "Add a
  status" for a new one and × to drop a stray. Notes are typed in the row. Both write
  back to the sheet immediately, matched by the key column, never by a remembered row
  number.
- **Opens on the work** — a blank status reads "Not contacted" and the tab opens
  filtered to those, with `Not contacted (n)` / `All (n)` buttons.
- **Filters** — search every column (including ones not displayed, which is where
  budget answers live) and filter by any column's real values with counts.
- **WhatsApp** — pick a message, tick any saved links, press **Open WhatsApp**. The
  message is pre-filled; a person still presses send. Links carry their own line of
  text ("Join our NEET PG community here:") so they read as an invitation.
- **Community** — a tick for "they're in", plus a menu recording *which* community.
  Seeded with **NEET PG community**; more can be added with a name and invite link.
- **Send to CRM** — ticked leads go to the Sales Hub. Select-all only takes what is on
  screen, never what a filter is hiding.
- **Sync** — re-reads the sheet every 2 minutes while the tab is visible.

## Open items

   cleared. Until it is set, a confirmation message goes out with no link.
   WhatsApp menu → Confirmation → *Add a link*, or the Community cell → *Add a community*.
2. **More communities.** Praveen has a list; only "NEET PG community" is seeded.
3. **Send to CRM is untested on purpose.** Creating a Sales Hub record trips the n8n
   round-robin (`QM1ypp3ZMt4YFTLr`), which assigns a counsellor **and WhatsApps the
   lead**. A "test" would message a real person. Test it with a lead you are happy to
   contact, or pause the workflow first.
4. **The sheet picker only lists sheets shared with the service account.** The
   dashboard signs in as `ig-dashboard-ga-reader@gc-dashboard-analytics.iam.gserviceaccount.com`,
   not as a person. Pasting a link is the agreed route; bulk-sharing was considered and
   dropped. Google Sheets API and Drive API are both enabled on project
   `gc-dashboard-analytics`.
5. **Adding someone to a WhatsApp community is manual** and always will be — there is
   no API for it, official or safe. The dashboard sends the invite and records who has
   been added.

## Next piece — Scheduler reels

Not started. `docs/SCHEDULER_REELS_SPEC.md` has the full audit with file and line
references. The short version:

- Our scheduler has one generic composer: no post/reel choice, no cover, no stories.
- **It does not publish to Instagram at all.** Pressing Publish writes a row to
  `mh_posts`; an n8n workflow outside this repo does the posting. The repo's own
  Instagram publish route handles photos only and has no caller.
- No video status polling, which is the likely cause of "sometimes it will not work" —
  Instagram needs a video to finish processing before it can be published.

Building it means four things in four places: the composer, a format + cover column on
`mh_posts`, a video publish path (`media_type=REELS`, `video_url`, `cover_url` or
`thumb_offset`), and the wait-for-processing step. Plus one decision: whether
publishing lives in the dashboard or in n8n, because right now it is split.

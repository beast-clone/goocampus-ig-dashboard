## What changed on 3–4 September

### Naming
- `"Hope UI"` (the purchased template's name) removed from the URL, components, CSS, assets and docs.
  Route is now `/dashboard/preview`; components are `Preview*`; CSS is `.preview-scope`.
  Branch renamed `feat/hope-ui-reskin` → **`feat/dashboard-reskin`**.
  The English word "hope" in marketing copy was deliberately left alone.

### Overview tab — the numbers were wrong
- **Reach** was a sum of 30 daily reach values, double-counting anyone who saw a post on more than one
  day. It read 11,12,658 for a month whose real unique reach was 5,06,986 — overstating by >2×.
  Now uses Meta's `metric_type=total_value`, which deduplicates the window. Capped at 30 days by Meta.
- **Engagement / Profile Visits / Eng. Rate** were not measured at all — engagement was `reach × 6%`
  and profile visits `35% of that`, so Eng. Rate could only ever display 6%. Instagram *does* expose
  `total_interactions` and `profile_views`; both are now real, and the `EST` badges are gone.
  Their trend arrows were fabricated too (reach trend × 0.9 / × 0.7) and now compare against the
  previous window.
- **Daily series was shifted a day.** `d.toISOString()` in IST rolls local midnight back a day, so the
  first point always drew a phantom 0 and the last day was dropped. Fixed to local calendar dates.
- Chart had no axes at all; it now has a labelled y-scale, dates, and a caption.

### Ads tab
- New **"Live right now"** section above the AI Ads Analyst, grouped by campaign, showing what is
  actually switched on (Meta `effective_status`, which rolls parents in — `status` alone would lie).
- Each campaign is judged by **its own objective**: clicks for LINK_CLICKS/traffic, leads otherwise.
- A leads campaign pointing at a domain without the pixel reads **"not tracked"** instead of `0`.
  This matters: `12thplus.com Traffic Ads` is set to `OUTCOME_LEADS` despite its name, and reports 0
  only because pixel `1387753849107574` is on goocampusevents.com and never on 12thplus.com. Every
  campaign that keeps the click inside Meta (Instant Form / Messenger) reports leads fine.
  `PIXEL_TRACKED_DOMAINS` in `lib/meta-ads.ts` is the one place to update when that pixel is installed.

### Scheduler — LinkedIn PDF carousels
- A multi-image LinkedIn post gets reordered by LinkedIn, so decks are exported as one PDF.
  Uploader now accepts PDF; webp/mov/webm dropped (in the route **and** on the Supabase bucket —
  storage enforces its own mime list and was returning a confusing 502 until it matched).
- LinkedIn documents use a different endpoint from images (`/rest/documents`, PUT, title required).
- **A PDF never goes to Meta.** Images → Instagram/Facebook, PDF → LinkedIn, from one Publish and one
  schedule time. A PDF-only post skips the Meta queue entirely.
- "Also post to LinkedIn" ticks itself; disabled for GooCampus India, which has no LinkedIn page.
- **Verified live end to end** on both pages (posted and deleted): manual publish, and a scheduled
  post that fired from the cron.

### LinkedIn token — no longer expires
- `LINKEDIN_CLIENT_ID` had been pointing at **GC World Pages API** while the tokens were issued by
  **GC Main Pages API** (`86fmmm22d2ca7i`). Corrected in `.env.local`, along with the client secret.
- `lib/linkedin-refresh.ts` renews the access token when it is inside 14 days of expiry, storing it in
  Supabase `mh_integration_tokens` (a deployed build cannot rewrite its own env). The rotated refresh
  token is stored too, under `linkedin_refresh` — missing that works exactly once.
- The cron worker calls it each tick. Token currently valid to **1 Nov 2026**, scopes include
  `w_organization_social`.

### Build
- `next build` had been failing on pdfjs (`import.meta` outside module code) since long before this
  work. Two pages load pdfjs; the V2 one was fixed months ago and the V1 one was missed. Fixed.
  **`npm run build` now exits 0.**

### Voice dictation (new)
`components/VoiceInput.tsx` — `useVoiceInput` hook + `MicButton`. Chrome's built-in speech API, no key,
no cost. Wired into four fields: Ask/search palette, scheduler caption (both boxes), Content Studio
topic, Content Studio draft editor.
- Chrome ends a speech session after a few seconds of silence — `continuous: true` does **not** prevent
  it. Sessions auto-restart so dictation survives pauses, and stop after **2 minutes** with nothing
  heard (it previously stayed open indefinitely).
- Warns and names the device when the mic produces no audio at all. Threshold is exactly 0 on purpose:
  a live mic always has a noise floor, so anything above 0 means the user simply hasn't spoken.
- Shortcuts: **⌃Space** or **⌘K** open search; **⌘D** toggles dictation in the focused field.
  ⌘Space is impossible — macOS binds it to Spotlight and the event never reaches a browser tab
  (checked against `com.apple.symbolichotkeys`: id 64 enabled, id 60 ⌃Space disabled, which is what
  frees Ctrl+Space on this Mac).
- Also fixed: the search palette was painted over by the page header. It renders inside the sidebar
  `<aside>`, which is `position: sticky` — and sticky always creates a stacking context, so `z-[200]`
  only ranked it within the sidebar. Now portalled to `document.body`.

are built from July's `main`. So: deploy first, then a two-node n8n workflow (Schedule → HTTP).

### 4. Chrome microphone on this Mac
Chrome was set to **"Camo Microphone (Virtual)"**, which emits pure silence — this is what made
dictation look broken for an hour. Peak 0 vs 52 on the built-in mic. If voice input ever "does
nothing", check the device first: padlock icon → Microphone.

## Things worth not re-learning

- **Push to `feat/dashboard-reskin`**, never `git push origin main` (it silently no-ops and loses work).
- Meta caps reach/insight windows at **30 days**; longer ranges are walked month by month.
- Meta's `no-speech`, and Instagram's silent `mockInsights()` fallback, both look like working code.
  When a number looks wrong, verify against the API directly rather than trusting the dashboard.
